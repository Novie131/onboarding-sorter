# 報到文件分類網頁（onboarding-sorter）

把「一整疊新進人員報到文件的掃描檔」自動切成每個人一份：判斷每份文件的種類，用地端視覺模型讀手寫姓名／學號並對應到名單，建好資料夾、改好檔名，最後打包成一個 zip 下載。

- 以 [Streamlit](https://streamlit.io/) 製作的網頁介面，在本機（例如 Raspberry Pi）執行
- 切文件、分種類完全離線，不需要辨識手寫字
- AI 配對使用 **OpenAI 相容 API**（Ollama／vLLM 皆可），只送出姓名欄／學號欄的小圖
- 沒設定 AI 也能用，會改成「依名單順序」預設配對
- 附加功能：合併多個 PDF

## 專案結構

```
onboarding-sorter/
├─ app.py                  Streamlit 網頁介面
├─ core.py                 核心邏輯：切文件、分類、裁切、打包 zip（不含介面）
├─ ai_match.py             呼叫地端視覺模型，配對手寫姓名／學號
├─ check_llm.py            檢查 .env 設定的模型伺服器能不能用
├─ requirements.txt        Python 套件
├─ .env.example            模型設定範本（複製成 .env 後填寫）
├─ .streamlit/config.toml  Streamlit 伺服器設定（埠號、上傳上限等）
├─ 使用說明.txt             給使用者看的純文字說明
└─ Document/Build.md       建置說明與參考程式碼
```

## 安裝

需要 Python 3.10 以上。

```bash
git clone https://github.com/Novie131/onboarding-sorter.git
cd onboarding-sorter
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env      # 要用 AI 配對時再填寫，見下方
```

使用的套件：`streamlit`、`pypdfium2`、`numpy`、`pillow`、`requests`、`python-dotenv`。PDF 處理使用 pypdfium2，不需要另外安裝 poppler。

## 啟動服務

在背景啟動：

```bash
cd onboarding-sorter
setsid nohup .venv/bin/python -m streamlit run app.py --server.headless true > streamlit.log 2>&1 < /dev/null &
```

在瀏覽器打開：

- 本機：http://localhost:8501
- 內網其他電腦：`http://<這台電腦的 IP>:8501`

停止服務：

```bash
pkill -f "[s]treamlit run app.py"
```

> 改了 `.env` 之後，要先停止再啟動，設定才會生效。

`.streamlit/config.toml` 預設 `address = "0.0.0.0"`，同一個內網都連得到。只想讓本機使用的話，改成 `"localhost"`。

## 設定 AI 模型

AI 會讀「健康聲明書」上的手寫姓名、「學習指導實施計畫」上的學號，自動對應到名單上的人。模型要放在你們自己、有獨立顯示卡的伺服器上，建議用 Ollama 跑 `gemma4:26b`（vLLM 也可以，換伺服器只要改 `.env`）。

1. 打開 `.env`（從 `.env.example` 複製來的）。
2. 填寫：

   | 變數 | 說明 | 預設值 |
   |---|---|---|
   | `LLM_BASE_URL` | 模型伺服器網址，**結尾一定要有 `/v1`**。Ollama 例：`http://<IP>:11434/v1`；vLLM 例：`http://<IP>:8000/v1` | （必填） |
   | `LLM_MODEL` | 模型名稱。Ollama 看 `ollama ls` 的 NAME 欄；vLLM 看 `curl <網址>/v1/models` 的 `id` | （必填） |
   | `LLM_API_KEY` | 伺服器有設 API 金鑰才填 | 空 |
   | `LLM_TIMEOUT` | 每次請求最多等幾秒 | `120` |
   | `LLM_MAX_TOKENS` | AI 回覆的 token 上限 | `1024` |
   | `LLM_EXTRA_BODY` | 進階：額外加進請求的 JSON 參數 | 空 |

3. 存檔後重新啟動服務。
4. 測試連線，兩種方法擇一：
   - 執行 `.venv/bin/python check_llm.py`，看到「✓ 連線成功」和「✓ 看圖正常」就可以了（會顯示回應花了幾秒）。
   - 在網頁左側側邊欄按「測試連線」。

### 常見問題

- **出現「模型沒有回覆內容…請調高 LLM_MAX_TOKENS」**：Gemma 4 會先「思考」再回答，上限太小時答案會被截掉。把 `LLM_MAX_TOKENS` 改成 `2048` 後重新啟動。
- **第一次分析特別慢或逾時**：模型要先載入顯示卡，稍等一下再按一次「開始分析」。
- **連不到伺服器**：確認 IP、埠號，以及模型伺服器有開放內網連線（Ollama 要設定 `OLLAMA_HOST=0.0.0.0:11434`）。

### 沒設定模型時

網頁照常可用，會「依名單順序」預設配對：名單照掃描順序貼上，下一步就不用調整。只是「夾在別人那套後面的學習指導實施計畫」要自己選是誰的。

## 使用步驟

1. **丟入掃描檔**
   把掃描好的 PDF 拖進網頁。可以一次丟好幾個，程式會依「檔名順序」接起來（掃描機的檔名含時間，所以就是掃描的順序）。

2. **貼上名單**
   每行一位，寫「學號 姓名」即可：

   ```
   1411230001 王小明
   ```

   也可以直接從 Excel 複製「組別、學號、姓名」幾欄貼上。有設定 AI 的話，名單順序不限。
   只補交「學習指導實施計畫」的人（例如上一批的同學）**也要放進名單**。

3. **按「開始分析」**
   程式會切出每一套文件、分出每份文件的種類，再請 AI 讀姓名／學號並自動選好人。畫面會顯示總頁數、略過的空白頁數、找到幾套文件、幾組學習指導實施計畫、名單有幾位。

4. **核對（很重要）**
   - 上半部：每一套文件一行。左邊是健康聲明書上的手寫姓名，右邊是 AI 選的人（可以自己改），下面顯示型態同意書是哪一種（研究獎助生／兼任研究助理）和「AI 讀到『…』」。
   - 下半部：每一組「學習指導實施計畫」一行。左邊是表單上的學號、姓名，右邊是 AI 依學號選的人（可以自己改）。
   - **黃色的一定要仔細看**，必要時自己改選。其他的也建議快速掃過，確認左右一致。
   - 某一套／某一組不要輸出，就選「（略過）」。

5. **按「分類並打包」，再按「下載壓縮檔」**，完成。

## 輸出內容

```
報到文件分類_日期_時間.zip
├─ 組別/學號_姓名/
│   ├─ 姓名-健康.pdf                          個資同意書 + 健康聲明書 2 頁
│   ├─ 姓名-型態.pdf                          勾「兼任研究助理」的型態同意書
│   ├─ 國科會計畫-姓名-型態.pdf               勾「研究獎助生」的型態同意書
│   ├─ 國科會計畫-姓名-學習指導實施計畫.pdf   實施計畫 2 頁 + 評量表 1 頁
│   └─ 姓名-其他.pdf                          認不出來的頁（正常不會出現）
└─ 分類清單.csv                               每個檔案對應原始掃描檔的第幾頁（可用 Excel 開）
```

- 「國科會計畫-」開頭的檔案＝研究獎助生的文件。
- 沒有的文件就不會產生那個檔，例如一般人只有「健康」和「型態」兩個檔。
- 只補交實施計畫的人，資料夾裡只有那一個檔。
- 名單沒寫組別時，就沒有組別那一層資料夾。
- 「通知」和「體檢項目表」是大家都一樣的印刷品，不會輸出。
- 型態同意書是橫式表格，掃描起來是側躺的，程式**不會**轉正（輸出頁面一律維持原始方向）。

## 判斷原理

**使用前提**：每個人的文件前 5 頁要照這個順序疊好再掃描：

```
通知 → 個資同意書 → 健康聲明書（2 頁） → 體檢項目表
```

後面再接型態同意書、學習指導實施計畫（順序不限）。整份掃描檔的第一張非空白頁一定要是「通知」。

- **切文件**：每一套最前面那張「通知」是大家都一樣的印刷品，用外觀相似度判斷「新的一套從這裡開始」，再依固定順序切出各個表格。雙面掃描的空白背面會自動跳過。
- **分種類**（體檢項目表之後的頁）：
  - 側躺的橫式表格 → 型態同意書。看「指導教授的紅色印章」蓋在哪一欄：蓋在「研究獎助生」欄 → 國科會計畫；蓋在「兼任研究助理」欄 → 一般型態。
  - 直式的 3 頁 → 學習指導實施計畫（2 頁）＋評量表（1 頁）。
- **認人**：
  - 每一套：把「健康聲明書姓名欄小圖」連同名單交給 AI，問它「這是名單上的誰」。
  - 學習指導實施計畫：讀表單上的「學號」，與名單學號完全相同就直接認定，所以夾在別人那套後面的實施計畫也會歸到正確的人。
  - AI 也會看錯，黃色的一定要人工確認。

## 黃色提醒說明

黃色提醒不會擋住操作，只是請你多看一眼。

| 提醒 | 意思 |
|---|---|
| AI 讀到「…」，沒把握，請確認 | AI 不確定、讀錯字，或沒找到對應的人 |
| 型態同意書判斷不出勾哪一型 | 沒蓋紅色印章、用黑色章，或章蓋在中間。檔案會先歸成一般「型態」 |
| 有 2 張勾「…」的型態同意書 | 同一種型態有 2 張，會合併成同一個檔 |
| 沒有找到型態同意書 | 這個人可能沒交，或掃描時漏掉了 |
| 同一套裡的第 2 組，可能是別人的 | 這套後面多夾了一組實施計畫，請對照學號選對人 |
| 這組有 ○ 頁（正常是 3 頁） | 實施計畫或評量表可能少了一張 |
| 第 ○ 頁認不出是什麼文件 | 會另存成「姓名-其他.pdf」 |
| 這一套只有 ○ 頁，可能缺頁 | 這個人可能少交了某一張，或掃描時漏掉了 |
| 第 5 頁看起來不是體檢項目表，頁序可能不對 | 這一套的紙可能疊錯順序 |
| 第 ○ 頁在第一份「通知」之前，已略過 | 掃描檔最前面有非通知的頁面，那些頁不會輸出 |

## 附加功能：合併 PDF

網頁上方切到「合併 PDF」分頁：

1. 選擇要合併的 PDF（至少 2 個，可一次多選）。
2. 選擇合併順序：依檔名（預設）或依加入順序。畫面會列出順序和每個檔案的頁數。
3. 按「合併」，再按「下載合併後的 PDF」。

頁面維持原本的方向，這個功能不會用到 AI。

## 隱私

- 掃描檔只在執行這個網頁的電腦上處理。
- 有設定 AI 時，**只有**兩種小圖會送到 `.env` 設定的模型伺服器：健康聲明書的姓名欄、學習指導實施計畫的學號／姓名欄。都不含身分證字號，也不會送出整頁或個資同意書。
- 網頁預設開放內網使用，同一個內網的人都能連進來，不需要登入。**請不要在路由器上把 8501 埠轉發到外網。**
- `.env`（可能含 API 金鑰）已列在 `.gitignore`，不會被提交。

## 已知限制

- 前 5 頁順序固定，第一張非空白頁必須是通知頁。表單版本或順序改了，要調整 `core.py` 的 `Packet` 索引與裁切座標。
- 型態判斷依賴「指導教授在勾選欄蓋紅色印章」。沒蓋章、用黑色章或蓋到中間時會顯示「判斷不出」，需人工確認。
- 實施計畫的參考頁是文件中第一張直式後段頁；若某份掃描檔的後段第一張不是實施計畫第 1 頁，分組可能出錯（會出現頁數不是 3 的提醒）。
- AI 配對準確度取決於模型和字跡；`ai_match.py` 的 `CONFIDENT = 0.7`、`MIN_SCORE = 0.6` 可依實際情況調整。
- 「會先思考」的模型若思考過長，答案會被截掉；調高 `LLM_MAX_TOKENS` 即可，代價是每張圖稍慢。
